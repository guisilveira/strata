# Spec — Run executable files from the context menu

## Ticket

| Field | Value |
| --- | --- |
| Issue | [#844](https://github.com/lgse/strata/issues/844) |
| Title | `feat(browser): add a Run option for executable files` |
| Branch | `feat/844-run-executable-context-menu` |
| Priority | P4 |
| Type | Enhancement |

## Problem

Strata only offers to run an executable when normal file activation fails because
GIO has no MIME handler. Executable files with a registered handler, including
AppImages, therefore have no explicit way to run from the browser.

## Scope

- Add a `Run` action to the item context menu when exactly one selected item is a
  native, regular file with at least one execute permission bit.
- Keep the existing `Open` and `Open With…` actions available when the file has
  registered handlers.
- Reuse the existing `Run this program?` confirmation and launch path.
- Apply the action consistently to Columns, Icons, List, and inline search result
  context menus through the shared item-menu implementation.
- Do not show `Run` for directories, non-executable files, remote locations,
  Trash items, or multi-selection.

## Design

1. Move the regular-executable predicate and confirmed launch entry point in
   `src/ui/browser/desktop.rs` to browser-internal visibility so activation and
   context-menu code share one policy and one confirmation flow.
2. Add the `Run` row in `src/ui/browser/context_menu.rs` only for an eligible
   single-item selection. Resolve the selected location again when the action is
   invoked, following the existing menu callback lifetime and selection rules.
3. Use an existing Lucide asset appropriate for execution. Do not add a new icon
   unless no suitable bundled icon exists.
4. Preserve the current activation fallback: an executable without a handler
   still reaches the same confirmation after normal activation fails.

## Acceptance criteria

- An executable regular file with a MIME handler shows `Open`, `Open With…`, and
  `Run`; choosing `Run` opens the existing confirmation dialog.
- Confirming launches the selected file; cancelling or closing the dialog does
  not launch it.
- An executable regular file without a MIME handler remains runnable both by
  activation fallback and by the explicit context-menu action.
- A non-executable regular file, directory, remote item, Trash item, and
  multi-selection do not show `Run`.
- Pointer and keyboard-opened context menus behave identically in Columns, Icons,
  List, and inline search results.

## Validation

- Keep `src/ui/browser/desktop/tests.rs` as the coverage owner for the shared
  eligibility predicate; its existing regression covers regular executable
  files, missing execute bits, directories, and missing native paths.
- Extend the shared context-menu tests under
  `src/ui/browser/context_menu/tests/` to verify visibility across browser modes
  and exclusion for unsupported selections.
- Extend `tests/e2e/scenarios/test_dialogs_and_menus.py` to exercise `Run` from
  the context menu, including confirmation cancellation and launch.
- Run the focused Rust tests with `./scripts/test-headless.py` and the selected
  E2E scenario with the canonical `./scripts/e2e.sh` runner; confirm each filter
  selects at least one test.

## Out of scope

- Changing execute permissions from the context menu.
- Running directories, remote files, or multiple files at once.
- Removing or changing MIME-handler activation, `Open`, or `Open With…`.
- Shipping Strata itself as an AppImage.
